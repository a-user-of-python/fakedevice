FakeDevice — stage 2

A lightweight fake iPhone (t8030) that runs the real iOS kernel — the actual kernelcache file, not converted, not recompiled — interpreted instruction by instruction right here in this tab.

Stage 2: the page now starts the kernel the way iBoot does. It parses the kernel file, loads every segment at its real address, builds the boot_args startup record and a small device tree, and jumps to the kernel's true entry point with X0 pointing at them. The kernel then runs its own start code, builds its own page tables, and turns its MMU on. From there it keeps executing in virtual memory until it reaches something the fake hardware doesn't have yet — right now that's a data read at address 0x1, about 25,861 instructions in, before its serial console is even awake (so the serial pane stays empty for the kernel — that's expected at this stage).

The backdoor (below) is open access straight into the fake phone: inspect or change any memory or register, set breakpoints, single-step, patch instructions on the fly, or type into its serial port. The same machine is also exposed to this tab's JavaScript console as window.fakedevice.
