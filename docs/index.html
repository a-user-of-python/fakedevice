FakeDevice — XNU in a browser tab

A lightweight fake iPhone (t8030) that runs the real iOS kernel — the actual kernelcache file, not converted, not recompiled — interpreted instruction by instruction right here in this tab. The fake BootROM checks the image, the fake LLB brings up memory, and the fake iBoot loads the real kernel and jumps to it, the same handoffs a real iPhone makes (BootROM → LLB → iBoot → kernel).

Auto download

Like the FakeDevice apps, this page keeps everything separate — and fetches what it can by itself. When the page opened, it downloaded the iPhone 11 translator pack from this site automatically and loaded it (the pack is the whole fake machine — memory map, serial port, CPU layout, boot settings — as data; watch the machine log below).

The kernel is the one piece the page cannot pull by itself: it lives inside Apple's iOS 14.8 update file (the IPSW), and Apple's servers don't give web pages permission to reach inside that file — the page tried, and the browser blocks it. So the working path is one extra step, with the page doing all the unwrapping:

Download the iOS 14.8 IPSW from Apple (about 6 GB)

…then drop the downloaded IPSW here (or pick it with the file button). The page extracts the kernelcache itself, in this tab: it unpacks the ZIP, unwraps the IM4P container, and LZFSE-decodes it with a small WebAssembly build of Apple's own LZFSE decoder — then checks the result against the genuine kernel's SHA-256 fingerprint before booting it. You can also drop a kernelcache.release file (IM4P) or an already-extracted kernelcache.raw directly. Nothing ever leaves your device — the page reads everything locally.

Where the boot stands

This build runs the real kernel past 200 million instructions with zero exceptions — the fake CPU hands every fault to the kernel's own exception handlers, the way real hardware does. The kernel then settles into a wait loop: the leading suspect is timer interrupts, which the fake machine doesn't generate yet. The serial pane stays empty — the console still isn't awake that early — and this is not a full boot yet. Finding and fixing what the kernel is waiting for is the current job.

The backdoor (below) is open access straight into the fake phone: inspect or change any memory or register, set breakpoints, single-step, patch instructions on the fly, or type into its serial port. The same machine is also exposed to this tab's JavaScript console as window.fakedevice.
